Bus Booking Website

Type: Booking-flow practice project

Primary stack: HTML, CSS, JavaScript

Live site: mezbaul-haque.github.io/swiftbus/

Project Goal

I built this project to practice a real-world multi-step user flow: search route, choose departure, select seats, review fare, and confirm booking details. The main objective was improving usability in form-heavy interfaces.

Core Features

The prototype includes route and date inputs, seat map interaction, fare calculation display, and a booking summary section. I focused on clear labels, simple error handling, and a straightforward progression from search to confirmation.

Implementation Approach

I separated structure and style cleanly so layout updates would not break behavior. JavaScript logic was kept modular for seat state changes and fare updates. This made it easier to test edge cases like invalid seat combinations or missing passenger details.

Challenges and Solutions

The hardest part was keeping state consistent across steps. To solve this, I tracked selected values in a single object and updated visible summary blocks after each user action. I also added feedback text so users understand why an action fails.

Result and Learning

This project helped me understand practical UI state management, user flow sequencing, and defensive form validation. The structure can be extended with backend APIs for real seat inventory and payment integration in future versions.
